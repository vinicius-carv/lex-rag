# lex-rag Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A RAG CLI/API over the CF88 and CDC that answers in Portuguese with verified article citations, plus an eval harness reporting retrieval and faithfulness metrics against baselines.

**Architecture:** Planalto HTML snapshots are parsed into articles, chunked (article = chunk, split by inciso when long) and stored in Postgres with a tsvector and a pgvector column. Retrieval runs keyword, dense or hybrid (RRF). A chat model returns JSON with citations that Java verifies against article text. Embeddings and answers go through a recording layer so CI replays without models.

**Tech Stack:** Java 21, Spring Boot 4.1.2 (parent POM, as doc-extract), spring-boot-starter-web + starter-jdbc, PostgreSQL driver, `com.pgvector:pgvector` 0.1.6, LangChain4j 1.24.0 (`langchain4j-ollama`, `langchain4j-anthropic`), jsoup 1.24.1, Jackson (Boot-managed), Testcontainers (Boot-managed), JUnit 5.

**Spec:** `docs/superpowers/specs/2026-11-22-lex-rag-design.md` (read it; this plan does not repeat its rules).

## Global Constraints

- Package root `io.github.viniciuscarv.lexrag`; Maven wrapper; artifact `lex-rag`, version `0.1.0-SNAPSHOT`.
- Plain JDBC (`JdbcTemplate`) for both full-text and vectors; LangChain4j only for model clients. (Builder's call per spec: the pgvector store is still beta and hybrid needs SQL anyway.)
- Postgres image pinned: `pgvector/pgvector:0.8.7-pg18` (compose, Testcontainers, CI).
- Snapshots are windows-1252; decode with `Charset.forName("windows-1252")`.
- Article ID format `<law>:art<N>[-<letter lowercase>]` — `cdc:art49`, `cf88:art5`, `cf88:art103-a`.
- Chunk max 1,500 chars; prompt budget 6,000 chars over top 5 articles; RRF `k=60`, 50 candidates per side.
- No secrets anywhere: `ANTHROPIC_API_KEY` only read from env; recordings store prompts/answers only, never headers.
- Commit messages: English conventional commits, ending with the attribution lines:
  `Generated with AI` / blank / `Co-Authored-By: AI <ai@example.com>`.
- Default test run (`./mvnw verify`) needs Docker (Testcontainers) but no network models; `@Tag("live")` tests are excluded unless `-Plive`.

## Review Focus

1. Planalto markup quirks: article starts split across `<a>`/`<span>` tags, `Art. 1º` vs `Art. 10`, `Art. 5o` with letter o, non-breaking spaces — parser must yield the expected article counts on the real snapshots (Task 1 count test).
2. Quote text with different whitespace, curly quotes, `§`/`º` variants or a trailing ellipsis from the model must still VERIFY (Task 2 tests).
3. Questions with characters that break `websearch_to_tsquery`-style parsing (quotes, `?`, `-`, `§`) must not throw (Task 3 test with `"O que diz o art. 5º, § 1º - \"direitos\"?"`).
4. Model returns JSON wrapped in ```json fences or with prose before it: strip fences/leading text before parsing; truly malformed → retry once → failed (Task 5 tests).
5. Replay mode with a missing recording must fail loudly with the key and text prefix, not silently call a live model or return zeros (Task 4 test).
